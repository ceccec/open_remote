# OpenRemote Rails

Rails application mirroring OpenRemote Java manager functionality.

## Documentation

### Generating Documentation

```bash
# Generate YARD documentation
bundle exec rake doc:generate

# Generate VitePress documentation from components and tests
bundle exec rake docs:from_tests

# Run tests and generate all documentation (YARD + VitePress)
bundle exec rspec  # Auto-generates docs if GENERATE_DOCS != "false"

# Run tests with coverage and generate documentation
bundle exec rake test:coverage_doc
```

### Viewing Documentation

- **YARD API Documentation**: `doc/index.html` (generated by YARD)
- **VitePress Documentation**: `docs/` directory (auto-discovered from Rails components)
  - View locally: `npm run docs:dev`
  - Build for production: `npm run docs:build`
  - **GitHub Pages**: Automatically deployed on push to `main` branch
- **Test Coverage**: `coverage/index.html` (generated by SimpleCov)

### VitePress Documentation

The VitePress documentation system automatically discovers all Rails components:

- **Models** - ActiveRecord models, associations, and methods
- **Controllers** - ActionController classes and actions  
- **Services** - Service objects and business logic
- **Jobs** - ActiveJob background jobs
- **Concerns** - Shared modules and mixins

All components are automatically scanned from the `app/` directory structure, and examples are extracted from RSpec test files. The documentation is organized by component type with a searchable sidebar navigation.

**Accessing Documentation:**

- **Development**: Run `npm run docs:dev` to start VitePress dev server (separate port)
- **Local Production**: Build with `bundle exec rake docs:build` - docs are served at root (`/`) of the Rails app
- **GitHub Pages**: Automatically deployed on push to `main` branch - see [GitHub Pages Setup](.github/PAGES_SETUP.md)
- **Fallback**: If docs aren't built locally, root redirects to RailsAdmin at `/api`

## Authentication

The application implements Devise-like authentication features without Devise:

- **Email Confirmation**: Users must confirm their email before logging in
- **Password Reset**: Users can reset passwords via email (6-hour expiration)
- **Remember Me**: Users can stay logged in for 2 weeks
- **Account Locking**: Accounts lock after 5 failed login attempts (2-hour lock)

### Default Admin User (Development/Test Only)

- **Email**: Configurable via `SUPER_ADMIN_EMAIL` environment variable (default: `admin@openremote.local`)
- **Password**: Randomly generated secure password (16 characters)

⚠️ **Security**: 
- Default credentials are only created in development and test environments
- Password is randomly generated and displayed once during seeding
- **Never saved to files** - use a password manager to store it securely
- Email can be customized via `SUPER_ADMIN_EMAIL` environment variable

**Example:**
```bash
# Use custom email
SUPER_ADMIN_EMAIL=super@admin.local bundle exec rails db:seed

# Use default email
bundle exec rails db:seed
```

**Note**: The password is shown in the console output during seeding. Save it securely immediately as it won't be displayed again.

## Role-Based Access Control

Uses Rolify for role management:

- **Admin**: Full access to everything, including user/role management
- **Manager**: Can manage assets, rules, data points, notifications; read-only for users
- **Viewer**: Read-only access to assets, rules, and data
- **Guest**: No access (default for unauthenticated users)

### Assigning Roles

```ruby
# Add role to user
user.add_role(:manager)

# Add resource-scoped role
user.add_role(:manager, asset)

# Check role
user.has_role?(:admin)
user.has_role?(:manager, asset)
```

## RailsAdmin

RailsAdmin is mounted at `/api` and serves as the primary API interface.

1. User authentication (login)
2. Admin role or appropriate permissions
